<!-- sdlc:auto:start overview -->
Simple Calculator is a two-application repository generated by the Quorq AI SDLC platform: a React 19 single-page app (Vite-built) implementing approved, reviewed screens that currently run on seeded sample data, and a FastAPI 0.115 backend that starts with only a health check and a generated auth flow (login/me) implemented, with every other endpoint scaffolded as a typed stub awaiting real logic. The backend persists through SQLAlchemy models migrated by Alembic, defaulting to a local SQLite file for easy local startup, while PostgreSQL 16 (via docker-compose) is the approved production database and what the test suite expects. The frontend talks to the backend through a generated openapi-fetch client and a bearer-token session stored in localStorage.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Python 3.12 (matches backend/Dockerfile base image)

- pip (Python package installer)

<!-- sdlc:auto:start setup -->
1. Clone the repository.
2. cd backend && pip install -r requirements.txt
3. Optionally start PostgreSQL for the backend tests: docker-compose up -d (starts the 'db' service on port 5432 with user/db 'app').
4. cd backend && uvicorn app.main:app --reload (starts the API; it applies Alembic migrations and seeds users on startup; defaults to a local sqlite:///./app.db unless DATABASE_URL is set).
5. cd frontend && npm install
6. cd frontend && npm run dev (starts the Vite dev server; defaults to calling the backend at http://localhost:8000 unless VITE_API_BASE_URL is set).
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend endpoints are organized as one router per architecture component (app/routers/), included into app/main.py; unimplemented endpoints return a typed StubResponse rather than failing.
- Pydantic request/response models come in Create/Read pairs per entity (see UserCreate/UserRead in schemas.py) and all inherit ApiModel so JSON fields are camelCase.
- SQLAlchemy models (app/models.py) use typed Mapped columns, one class per entity in the approved data model.
- Database schema changes only via Alembic migrations (backend/alembic/versions/); app startup runs 'alembic upgrade head' rather than create_all.
- Database session is request-scoped via the get_db dependency, which always closes the session.
- Frontend API calls go exclusively through the generated client in src/api/client.ts (from npm run gen:api), never raw fetch.
- Session auth token is stored in localStorage and sent as a bearer header ahead of the shared project-id bearer (src/lib/api.ts).
- Component tests (Vitest) live beside the components they test; Playwright e2e specs live under frontend/e2e/.
- Both backend and frontend test runners emit JUnit XML to a fixed reports/junit/ path for the platform's test dashboard.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails at startup with 'alembic.ini is missing beside app/'. | Ensure alembic.ini and the alembic/ directory are present next to backend/app/ (they are copied into the Docker image and must exist in a local checkout too). |
| Frontend requests are blocked by CORS. | Set ALLOWED_ORIGINS (comma-separated) as an env var for the backend to include the frontend's origin; it defaults to the Vite dev server origins (localhost:5173 / 127.0.0.1:5173). |
| Backend tests fail to connect to a database. | Start PostgreSQL first with 'docker-compose up -d' and wait for its healthcheck to pass, or set DATABASE_URL as described in TESTING.md; the default SQLite file (app.db) is not what the test suite targets. |
| Frontend can't reach the API in dev. | Confirm the backend is running on http://localhost:8000, or set VITE_API_BASE_URL to point at a different backend URL. |
| 'npm run gen:api' fails to find a Python interpreter. | Set the PYTHON env var to the backend virtualenv's python, or ensure backend/.venv/bin/python exists (the script defaults to that path). |
<!-- sdlc:auto:end troubleshooting -->
